# Family Memory

Семейное дерево и общий архив рассказов, фотографий, аудио и видео.
Приложение работает в браузере, в том числе на телефоне, и размещается на своём сервере.
Одна установка — сервис для нескольких семей: у каждой своё закрытое пространство,
данные разных семей изолированы друг от друга.

Этот репозиторий — канонический исходный код проекта **Family Memory**.
«Семейное пространство» обозначает данные и участников одной семьи внутри сервиса,
а не второй проект или второй репозиторий.

## Возможности

- Люди и родственные связи в общем дереве: раздельные поля ФИО, точные и приблизительные даты, прежние фамилии, источники сведений.
- Ручное добавление и редактирование. Новые сведения видны сразу с автором; подтвердить их должен другой участник. Есть история изменений и отметка неточности.
- Архив историй, фотографий и записей со связями с людьми. Воспоминание может существовать самостоятельно, без извлечения фактов.
- Ассистент с текстовыми и голосовыми сообщениями. Он уточняет рассказ и предлагает изменения с цитатами; человек выбирает, что добавить в дерево.
- Telegram-вход, одобрение новых участников администратором, роли администратора, участника и наблюдателя. Для родственников без Telegram есть одноразовые гостевые ссылки.
- JSON-экспорт и полная резервная копия базы вместе с оригиналами файлов.

Исходная база пустая: в приложение не добавлены родственники или семейные истории.
Интерфейс сейчас на русском языке.

## Быстрый запуск локально

Нужны Node.js 24+, ffmpeg 7+ с ffprobe и `heif-convert` для фотографий HEIC.
На macOS: `brew install ffmpeg libheif`; на Debian Trixie:
`sudo apt install ffmpeg libheif-examples`. Docker-образ уже содержит эти программы.

```sh
git clone https://github.com/ilyaberdysh/family-memory.git
cd family-memory
npm ci
cp -n .env.example .env
npm run local
```

Откройте [http://127.0.0.1:4317](http://127.0.0.1:4317) и нажмите
«Открыть локальный просмотр». В пустой базе создаётся технический администратор;
карточка человека в дереве автоматически не создаётся. Для первого локального запуска
оставьте `ADMIN_EMAIL` пустым.

Локальный просмотр работает только на loopback, с `DEV_AUTH=1`, вне production.
Он не требует Telegram. Для повторного запуска используйте `npm run local`;
на macOS также доступен `start-local.command`. Сервер нужно перезапустить после
изменения `.env`, а страницу — обновить после изменения интерфейса.

### Telegram-вход при локальной разработке

Для проверки настоящего Telegram-входа зарегистрируйте в **BotFather → ваш бот →
Login Widget** оба точных URL:

```text
http://127.0.0.1:4317
http://127.0.0.1:4317/api/auth/telegram/callback
```

Запишите выданные `TELEGRAM_CLIENT_ID`, `TELEGRAM_CLIENT_SECRET` и числовой ID
личного аккаунта владельца в `ADMIN_TELEGRAM_ID` локального `.env`. Затем
запустите `npm run dev`, а не `npm run local`: обычный dev-запуск оставляет
`DEV_AUTH` выключенным и показывает реальный Telegram-вход. URL должны в точности
совпадать с `PUBLIC_ORIGIN` и callback; Telegram не перенаправляет на
незарегистрированные адреса. Если BotFather не разрешит HTTP loopback, для живой
проверки понадобится отдельный HTTPS-адрес или туннель, зарегистрированный тем же
способом.

Без `DATABASE_URL` локальный запуск использует встроенный PostgreSQL (PGlite)
в `data/pglite/`; файлы лежат в `data/files/<id семьи>/`.
Каталог данных и файлы `.env` не должны попадать в Git.

## Размещение на сервере

[Инструкция для Coolify](DEPLOYMENT.md) описывает установку из GitHub,
переменные окружения, HTTPS, постоянный том и подключение Telegram.
Можно сначала запустить пустое приложение, а Telegram настроить следующим шагом:
до подключения вход останется закрытым.

Записи хранятся в **PostgreSQL** (`DATABASE_URL`), загруженные файлы — в постоянном
томе, по каталогу на семью. Изоляция семей обеспечивается и кодом, и политиками
Row-Level Security базы. Redis и S3 не нужны. Запускайте один экземпляр приложения
и сохраняйте том между обновлениями. Установку прежней версии на SQLite переносит
`scripts/import-sqlite.mts` ([DEPLOYMENT.md](DEPLOYMENT.md#23-перенос-существующей-установки-на-sqlite)).

Для установки без Coolify есть `compose.yaml` с сервисом `postgres:17-alpine`.
Создайте `.env` из `.env.example`, задайте `PUBLIC_ORIGIN` с HTTPS и
`POSTGRES_PASSWORD` (только буквы и цифры: он входит в URL), настройте прокси и выполните:

```sh
docker compose up -d --build
docker compose logs --tail=100 app
```

Compose публикует порт `4317` только на loopback сервера. HTTPS-прокси должен
направлять запросы на `127.0.0.1:4317`. `docker compose down` сохраняет том;
флаг `-v` удаляет тома вместе с базой и архивом.

## Доступ и приглашения

Обычная ссылка `https://family.example.com/?join=1` открывает приглашение и
Telegram-вход. Она не предоставляет доступ к дереву. Новый участник указывает
фамилию, имя, необязательное отчество и телефон, затем ждёт одобрения администратора.
Телефон можно передать из Telegram с согласия пользователя или ввести вручную;
вручную введённый номер остаётся неподтверждённым. Входа по телефону, SMS и почте нет.

В приглашении видны название пространства и до пяти знакомых фамилий.
`FAMILY_SURNAMES` задаёт фамилии через запятую; список дополняется отдельными
полями текущих фамилий из дерева. Прежние (девичьи) фамилии публично не
показываются. Это публичная часть приглашения, доступная до входа. Остальные семейные данные требуют одобренного доступа.

После одобрения участник может выбрать свою существующую карточку кнопкой
«Это я» или пропустить этот шаг. Совпадение имени не приводит к автоматическому
объединению аккаунта и человека; данные карточки не переписываются.

Администратор может создать гостевую ссылку на один вход, действующую 7 дней,
с ролью участника или наблюдателя. Такой доступ заранее одобрен. Передавайте
ссылку лично её получателю. Для повторного входа гостя создавайте новую ссылку
из строки **его существующего аккаунта**, чтобы сохранить роль и авторство.
Гость не может быть администратором. Сессии действуют до 365 дней, если браузер
не очистит cookie раньше.

## Ассистент и данные

Диалог доступен автору и администратору. Текст или оригинал голосового сообщения
сохраняется до обращения к AI. Можно исправить последнюю расшифровку и повторить
обработку; ошибка не удаляет запись.

«Сохранить историю в архив» создаёт доступный семье снимок слов рассказчика со
ссылками на оригиналы. Продолжение диалога не меняет сохранённый снимок.
«Подготовить сведения» дополнительно создаёт предложения с цитатами. Принятые
человеком изменения появляются неподтверждёнными; другой участник проверяет их.
Ответы ассистента не используются как источники семейных фактов.

`OPENAI_API_KEY` необязателен: без него доступны ручное наполнение и архив.
Ключ хранится на сервере. При запуске AI аудио для расшифровки и текст для анализа
отправляются в OpenAI. Для ответа ассистента также передаются диалог, имя профиля,
имена людей в дереве и сведения о явно упомянутых людях. API оплачивается отдельно.
Локальные модели, непрерывный голосовой звонок и озвучивание ответов пока не подключены.

| Настройка | Значение по умолчанию |
| --- | --- |
| `TRANSCRIPTION_MODEL` | `whisper-1`; другие значения отклоняются, чтобы сохранять временные метки |
| `EXTRACTION_MODEL` | `gpt-4.1-mini` |
| `CHAT_MODEL` | `gpt-4.1-mini` |
| `CHAT_REQUEST_TIMEOUT_MS` | `90000` |
| `CHAT_MAX_OUTPUT_TOKENS` | `1200`, максимум `2000` |
| `MAX_UPLOAD_MB` | `250` на файл |
| `AI_MAX_DURATION_SECONDS` | `7200` |
| `AI_REQUEST_TIMEOUT_MS` | `120000` |
| `AI_PROCESS_TIMEOUT_MS` | `600000` |
| `MEDIA_MAX_DURATION_SECONDS` | `7200` |
| `MEDIA_PREVIEW_TIMEOUT_MS` | `180000` |
| `MEDIA_PREVIEW_MAX_MB` | `500` |

Оригиналы медиа сохраняются. Для неподдерживаемых браузером форматов сервер
локально готовит JPEG из HEIC, MP3 из аудио или MP4 H.264/AAC до 720p из видео.
Это не требует AI-ключа. Пути программ можно переопределить через `FFMPEG_PATH`,
`FFPROBE_PATH` и `HEIF_CONVERT_PATH`.

## Резервные копии

JSON-экспорт из интерфейса не включает оригиналы файлов. Для полной копии всех семей:

```sh
npx tsx scripts/backup.mts --data-dir ./data --out ../family-memory-backups/new-copy --app-stopped
```

`--out` должен указывать на новый каталог вне активного `DATA_DIR`. Скрипт читает
все таблицы одним согласованным снимком базы и пишет их в `database.ndjson`
(одна запись — одна строка JSON, без привязки к версии PostgreSQL), затем
копирует перечисленные в базе оригиналы и версии для браузера в
`files/<id семьи>/`. Финальный `manifest.json` содержит контрольные суммы и
число записей по семьям. Сессии, коды входа, секреты и временные файлы в копию
не входят; храните настройки отдельно в защищённом месте. `--link-dest <прежняя
копия>` связывает неизменившиеся файлы жёсткими ссылками вместо повторного
копирования. `--family <id>` выгружает одну семью.

С PostgreSQL (`--database-url` или `DATABASE_URL`) скрипт можно запускать при
работающем приложении. Встроенную базу PGlite может открыть только один процесс,
поэтому для неё нужен `--app-stopped`; работающее приложение делает снимки само.

Отсутствующий или повреждённый файл не останавливает копирование: копия
создаётся из всего, что удалось прочитать, проблемы перечисляются в манифесте,
а скрипт завершается с кодом `2` (чистая копия — `0`, ошибка — `1`).

Если задан `BACKUP_DIR`, приложение само делает такие снимки по расписанию
(`BACKUP_INTERVAL_HOURS`, по умолчанию раз в сутки) и хранит `BACKUP_KEEP`
последних; в Docker Compose это включено. Снимки лежат на том же диске, поэтому
копия на другом сервере всё равно нужна — пример в [DEPLOYMENT.md](DEPLOYMENT.md#6-резервные-копии-и-восстановление).

Проверка без изменений данных: `npx tsx scripts/verify.mts --data-dir ./data --app-stopped`
для рабочих базы и файлов и `npx tsx scripts/verify.mts --backup <копия>` для снимка.

Для Docker Compose:

```sh
snapshot="copy-$(date +%Y%m%d-%H%M%S)"
docker compose exec app node_modules/.bin/tsx scripts/backup.mts --out "/var/lib/family-space/backups/$snapshot"
mkdir -p ../family-memory-backups
chmod 700 ../family-memory-backups
docker compose cp "app:/var/lib/family-space/backups/$snapshot" "../family-memory-backups/$snapshot"
```

Переносите готовые копии за пределы тома и сервера приложения. Постоянный том
переживает обновление контейнера, но не заменяет резервную копию.

## Восстановление

Полное восстановление выполняется только в пустую базу. Скрипт проверяет
контрольные суммы, каждую строку выгрузки и соответствие файлов базе, затем в
одной транзакции записывает базу и переносит файлы в `<--to>/files/`:

```sh
npx tsx scripts/restore.mts --from ../family-memory-backups/new-copy --data-dir ../family-memory-restored --app-stopped
```

Для PostgreSQL вместо `--data-dir` укажите `--database-url` пустой базы и
`--to <DATA_DIR>` для файлов. `--family <id>` восстанавливает одну семью в базу,
где её ещё нет; существующие аккаунты при этом не перезаписываются. Копию,
созданную с проблемами, скрипт восстанавливает только с флагом `--allow-problems`
и перечисляет недостающие файлы.

Старые сессии не восстанавливаются, гостевые ссылки отзываются, прерванные
задания AI требуют ручного повторного запуска. Необязательный
`--admin-email owner@example.com` меняет email единственного аккаунта локального
просмотра (`admin@local.invalid`), сохраняя ID и авторство. Скрипты не загружают
`.env` автоматически: передавайте параметры явно или через окружение.
Копии прежнего формата (SQLite) переносятся через `scripts/import-sqlite.mts`.

## Разработка

React, TypeScript и Vite на клиенте; Express, PostgreSQL (PGlite для локального
просмотра и тестов) и локальные файлы на сервере. Ассистент использует assistant-ui и AI SDK, Telegram — OIDC.

```sh
npm test
npm run build
```

Проверки покрывают доступ и роли, Telegram-подписи и повторное использование
входа, гостевые ссылки, версии данных, независимое подтверждение, родственные
циклы, цитаты AI и закрытые файлы. Резервное копирование проверяется на
синтетическом архиве во временных каталогах: восстановление файлов байт в байт,
копии с отсутствующими и повреждёнными файлами, жёсткие ссылки на прежний снимок
(в том числе старого формата), полное восстановление в пустую базу, выгрузка и
восстановление одной семьи рядом с другими, `verify.mts`, перенос синтетической
установки на SQLite через `import-sqlite.mts`, расписание, ротация и прерывание
копирования. Тесты используют PGlite; с настоящим PostgreSQL сценарий копирования
и восстановления проверен вручную. Тесты не заменяют
проверку настоящего сервера: восстановите внешнюю копию хотя бы раз.
Сетевые интеграции в тестах подменяются: после настройки сервера отдельно
проверьте настоящий Telegram-вход, AI и запись с телефона.

Архитектурные договорённости описаны в [CONTRACT.md](CONTRACT.md), правила работы
с репозиторием — в [AGENTS.md](AGENTS.md), порядок изменений — в
[CONTRIBUTING.md](CONTRIBUTING.md). Используйте синтетические данные в тестах
и обезличивайте скриншоты перед публикацией issues и pull requests.

Исследование похожих проектов, ручных архивных процессов и возможных будущих
интеграций хранится в [docs/research-and-roadmap.md](docs/research-and-roadmap.md).
Это направления развития, а не функциональность текущей версии.
