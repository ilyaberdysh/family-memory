# Исследования и будущие источники

Зафиксировано 6 сентября 2026 года и перенесено в канонический репозиторий
Family Memory 9 сентября 2026 года. Это исследовательские заметки и направления
развития, а не обещания текущей версии.

## Замысел продукта

Family Memory создаётся прежде всего для одной семьи: дерево должно быть удобно
смотреть, а фотографии, даты, места, связи, истории, голос и документы — удобно
сохранять и обсуждать. Позже приложение сможет помогать искать возможные
совпадения во внешних архивах и генеалогических базах.

Главная продуктовая ниша находится между профессиональной генеалогической базой
и семейным альбомом, который приятно открыть вместе с родственниками:

1. Современный и простой режим просмотра для семьи.
2. Голос, характерные фразы, истории, фотографии, письма и семейные места рядом
   с датами и родственными связями.
3. Видимый источник каждого факта: «со слов», документ, внешний архив или
   гипотеза.
4. Внешний поиск создаёт только карточку возможного совпадения с объяснением и
   ссылкой на оригинал. Он никогда не меняет дерево автоматически.
5. Приватность по умолчанию, GEDCOM-экспорт и понятная полная резервная копия.

## Продукты и форматы для сравнения

- [Gramps Web](https://github.com/gramps-project/gramps-web) — зрелый benchmark:
  совместное редактирование, профили, источники, цитаты, медиа, карты, виды
  дерева, приватность, поиск, GEDCOM и REST API.
- [webtrees](https://github.com/fisharebest/webtrees) — зрелое self-hosted
  приложение с GEDCOM, совместной работой и детальными правилами доступа.
- [FamilyArchive](https://github.com/addison-moore/FamilyArchive) — близкое
  сочетание дерева и медиаархива: фото, видео, аудио, сканы, OCR, поиск,
  маркировка людей и GEDCOM. На дату исследования проект находился на стадии
  v0.1/user acceptance testing.
- [Family Book](https://github.com/tymrtn/family-book) — private/self-hosted
  дерево и архив с профилями, моментами, поездками, фотографиями и русской
  локализацией. GEDCOM и импорт мессенджеров были в roadmap.
- [My Family](https://github.com/cacack/my-family) — API-first проект с GEDCOM,
  картой, поиском, источниками, журналом изменений и отдельными ветками для
  непроверенных гипотез.
- [GENEALOGIX](https://github.com/genealogix/glx) — Git/YAML-формат с
  человекочитаемыми данными, evidence chain, историей изменений и GEDCOM. На
  дату исследования имел статус beta.

Полезный визуальный референс — круговая диаграмма FamilyTree, построенная вокруг
выбранного человека. Такой отдельный вид может быстро показывать ближайшие
поколения и связи.

## Проверка ценности до архивных интеграций

Первый честный тест — за неделю занести 15–30 настоящих людей. Для каждого
достаточно имени, связи, одной фотографии, даты или примерного года, места,
короткой истории и источника. Затем дать двум родственникам без подсказок:

- найти конкретного человека;
- понять, кем он им приходится;
- открыть фотографию или историю;
- добавить или исправить один факт.

Если родственники хотят продолжить и сами приносят материалы, идея работает.
Интеграции с архивами стоит начинать после этого теста.

До собственной реализации GEDCOM и сложного внешнего поиска полезно сравнить три
пути:

1. Поднять Gramps Web и неделю использовать его с настоящим небольшим деревом.
2. Если его модель данных подходит, но семейный интерфейс слишком сложен,
   рассмотреть собственный лёгкий UI поверх Gramps Web API или GEDCOM.
3. Продолжать полностью собственную систему только там, где это даёт заметно
   лучший семейный опыт и оправдывает стоимость сложных связей, дублей, дат,
   доступа и резервного копирования.

## Возможные источники и API

- [FamilySearch API](https://developers.familysearch.org/) — деревья, места,
  записи, фотографии и истории. Нужен одобренный API key; для исторических
  записей действуют отдельные ограничения.
- [Open Archives API](https://www.openarchieven.nl/api/docs/) — поиск и matching
  людей по открытым генеалогическим наборам Нидерландов, включая транскрипции и
  выгрузки.
- [Europeana APIs](https://api.europeana.eu/en) — культурно-исторические
  объекты, метаданные и IIIF-изображения европейских коллекций.
- [Archives Portal Europe](https://www.archivesportaleurope.net/) — описания
  архивных фондов в EAD и API для разрешённых учреждениями наборов.
- [Internet Archive APIs](https://archive.org/services/docs/api/) — книги,
  газеты, аудио, видео и метаданные.
- [Wikidata Query Service](https://query.wikidata.org/) — открытые связи для
  уже публичных исторических персон.
- [Открытые данные Росархива](https://archives.gov.ru/opendata) — справочники и
  описания фондов; наличие удобного person-search API нужно проверять отдельно
  для каждого набора.

Перед реализацией любой интеграции нужно заново проверить актуальность API,
условия доступа, лицензии, лимиты и допустимость хранения найденных материалов.
Основной формат Family Memory не должен зависеть от одного коммерческого сервиса.

## Практический ручной поиск

### ГИС УИАД

Искать по типу документа и территории, например «книга переписная крестьян
Тверского уезда». В подходящем результате открыть дело, выбрать цифровую копию
или удалённое использование и оформить услугу через Госуслуги.

В Family Memory сохранять оригинал, архивный шифр, название дела, страницы,
найденные имена и ссылку на исходную карточку.

### Familio

Искать фамилию и возможный населённый пункт, смотреть сканы и подтверждения.
Найденный населённый пункт использовать для более точного поиска в архивных
каталогах.

### Яндекс Поиск по архивам

Использовать [поиск по архивам](https://yandex.ru/archive/search) по фамилии,
имени, населённому пункту и другим известным данным. Проверять варианты фамилии
и близкие написания.

### FamilySearch

Искать людей и ветки на [FamilySearch](https://www.familysearch.org/ru/global)
по известным родственникам и населённым пунктам. Пересечение с чужим деревом
считать возможной связью, а не подтверждённым фактом, пока нет первичного
документа или независимого подтверждения.

## Возможная автоматизация

Автоматизированный поиск должен быть конвейером предложений, а не автозаполнением
дерева:

1. Пользователь выбирает человека и явно запускает поиск.
2. Приложение формирует минимальный запрос из разрешённых пользователем полей и
   вариантов написания.
3. Коннектор сохраняет ссылку на источник, дату поиска, исходные метаданные и
   допустимую копию материала.
4. Возможное совпадение получает объяснение: какие имя, место, дата и связи
   совпали или противоречат друг другу.
5. Человек отклоняет совпадение либо создаёт из него отдельное предложение
   факта/связи.
6. Обычные правила Family Memory — авторство, версия и независимое подтверждение
   — применяются уже после явного принятия предложения.

Нужно хранить исходный ответ провайдера отдельно от нормализованного факта,
чтобы обновление коннектора не переписывало семейную историю задним числом.

## Границы

- Не публиковать сведения о живых людях без их согласия.
- Всегда хранить оригинал документа и происхождение каждого извлечённого факта.
- Не принимать тёзку за родственника без подтверждающих связей.
- Отделять доказанный факт, внешнее утверждение и рабочую гипотезу.
- Не отправлять внешнему сервису больше семейных данных, чем нужно для явно
  запущенного поиска.
- Не принимать внешнее совпадение и не объединять людей автоматически.
