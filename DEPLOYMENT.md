# Развёртывание Family Memory в Coolify

Одна установка — одно закрытое семейное пространство. Для первого запуска
используйте пустой постоянный том: переносить локальную базу не требуется.
Telegram можно подключить после первого деплоя; до настройки вход будет закрыт.

## 1. Приложение из GitHub

В проекте Coolify создайте приложение из репозитория
`https://github.com/ilyaberdysh/family-memory` и задайте:

| Поле | Значение |
| --- | --- |
| Branch | `main` |
| Build Pack | `Dockerfile` |
| Base Directory | `/` |
| Dockerfile Location | `/Dockerfile` |
| Ports Exposes | `4317` |
| Port Mappings | Оставить пустым |
| Domain | Ваш HTTPS-адрес, например `https://family.example.com` |
| Replicas | `1` |

Команды установки, сборки и запуска задаёт Dockerfile. Отдельный статический
сервис для frontend не нужен. Домен направьте на сервер Coolify и включите HTTPS;
прокси должен обращаться к внутреннему порту `4317`.
[Dockerfile в Coolify](https://next.coolify.io/docs/applications/builds/dockerfile).

В **Advanced** включите **Consistent Container Names**, чтобы обновление сначала
останавливало старый контейнер. Одновременный запуск старого и нового экземпляров
на одной SQLite недопустим для фоновых заданий приложения; короткая пауза при
обновлении ожидаема. Если такого переключателя в вашей версии нет, остановите
приложение перед обновлением. Не подключайте production-том к preview deployments.
[Порядок rolling updates](https://next.coolify.io/docs/applications/deployments/rolling-updates).

## 2. База и файлы

Отдельный ресурс Database в Coolify создавать не нужно. Приложение уже использует
**SQLite**, а аудио, видео и фотографии сохраняет как файлы. PostgreSQL, Redis
и S3 в текущей версии не подключены; переменные `DATABASE_URL` и S3-реквизиты
приложение не использует.

До первого деплоя добавьте в **Persistent Storage** том:

| Поле | Значение |
| --- | --- |
| Type | Volume Mount / Docker Volume |
| Name | `family-memory-data` |
| Source Path | Оставить пустым для named volume |
| Destination Path | `/var/lib/family-space` |

Coolify может дописать UUID ресурса к имени тома — это нормально.
Путь внутри контейнера должен остаться именно `/var/lib/family-space`.
[Постоянные тома Coolify](https://coolify.io/docs/knowledge-base/persistent-storage).

При `DATA_DIR=/var/lib/family-space/data` в этом томе будут:

```text
/var/lib/family-space/
└── data/
    ├── family.sqlite
    ├── family.sqlite-wal  # могут присутствовать во время работы SQLite
    ├── family.sqlite-shm
    └── files/            # оригиналы и подготовленные версии медиа
```

Схема базы создаётся автоматически. Контейнер работает от `node` с UID/GID
`1000:1000`; каталогу нужны права записи для этого пользователя. Dockerfile
подготавливает родительский каталог. Если используете bind mount вместо нового
тома, заранее назначьте его каталогу на сервере владельца `1000:1000`.
Не меняйте права всех каталогов Coolify и не используйте `chmod 777`.

Не монтируйте том поверх `/app`: там находится код приложения.
Сохраняйте тот же том при redeploy. Удаление тома удалит и базу, и медиа.

## 3. Переменные окружения

Откройте **Environment Variables** приложения и перенесите значения из
[.env.coolify.example](.env.coolify.example), заменив домен своим.
Все эти переменные нужны во время выполнения. Для секретов выключите
**Build Variable**: сборке frontend они не нужны. Не используйте префикс `VITE_`
для ключей и не добавляйте `.env` в GitHub.
[Runtime-переменные Coolify](https://coolify.io/docs/knowledge-base/environment-variables).

Минимум для первого закрытого запуска:

```dotenv
NODE_ENV=production
DEV_AUTH=0
HOST=0.0.0.0
PORT=4317
TRUST_PROXY=1
PUBLIC_ORIGIN=https://family.example.com
DATA_DIR=/var/lib/family-space/data
SPACE_NAME=Семейное пространство
FAMILY_SURNAMES=
```

Замените `PUBLIC_ORIGIN` на свой фактический HTTPS-адрес, без пути и завершающего
`/`. Он должен совпадать с адресом в браузере. `TRUST_PROXY=1` рассчитан на один
прокси Coolify перед приложением. **`DEV_AUTH=0` обязателен в production.**

`FAMILY_SURNAMES` можно заполнить 3–5 фамилиями через запятую. Вместе с
`SPACE_NAME` они будут видны на публичном приглашении. При пустом значении
фамилии появятся по мере ручного заполнения дерева.

Следующие поля пока можно оставить пустыми или не создавать:

| Переменная | Когда нужна |
| --- | --- |
| `TELEGRAM_CLIENT_ID` | Подключение Telegram Login |
| `TELEGRAM_CLIENT_SECRET` | Секрет Telegram Login; только runtime |
| `ADMIN_TELEGRAM_ID` | Личный числовой Telegram ID владельца, задать до первого входа |
| `OPENAI_API_KEY` | Ассистент, расшифровка и извлечение сведений; только runtime |
| `ADMIN_EMAIL` | Только поиск прежнего администратора при переносе; для пустой базы не нужен |

Без Telegram-параметров сервер запускается, но вход недоступен. Без OpenAI-ключа
ручное наполнение и архив работают после входа, AI-обработка недоступна.
Дополнительные лимиты и модели перечислены в [.env.example](.env.example)
и [README.md](README.md#ассистент-и-данные).

## 4. Первый деплой

Нажмите **Deploy**. Health check в Dockerfile обращается к
`GET /api/auth/config` на порту `4317`; если задаёте проверку в Coolify вручную,
используйте тот же путь и ожидайте HTTP `200`.

Проверьте HTTPS-страницу входа. Без Telegram она должна сообщать, что вход пока
недоступен. Запрос `/api/state` без сессии должен возвращать `401`, а production
не должен показывать кнопку локального просмотра.

В терминале контейнера можно проверить хранилище без вывода секретов:

```sh
node -e "const fs=require('node:fs');const p=process.env.DATA_DIR;fs.accessSync(p,fs.constants.W_OK);console.log('Data directory is writable');console.log('SQLite exists:',fs.existsSync(p+'/family.sqlite'))"
```

До подключения пользователей проверьте свободные память и диск. Оригиналы медиа
и их браузерные версии занимают место в томе; размер сервера выбирайте по объёму
загрузок. Приложение не создаёт резервные копии автоматически.

## 5. Подключение Telegram

Этот шаг можно выполнить позже без пересоздания приложения или тома.

1. В мини-приложении **BotFather → ваш бот → Login Widget** добавьте Allowed URLs:
   `https://family.example.com` и
   `https://family.example.com/api/auth/telegram/callback`, заменив домен на свой.
2. Сохраните оттуда **Client ID** и **Client Secret** в `TELEGRAM_CLIENT_ID`
   и `TELEGRAM_CLIENT_SECRET`. Это отдельные реквизиты Login, не bot token.
   Алгоритм подписи оставьте **RS256**.
3. Задайте `ADMIN_TELEGRAM_ID`: числовой ID **личного Telegram-аккаунта владельца**,
   не ID бота. Сохраните настройки и выполните redeploy.
4. В пустую базу первым должен войти именно владелец с этим ID. До этого
   не распространяйте ссылку регистрации: автоматический первый администратор
   создаётся только для явно указанного ID и пустой таблицы пользователей.

Приложение использует серверный OIDC Authorization Code flow с PKCE и проверкой
подписанного ID-токена. [Официальная инструкция Telegram Login](https://core.telegram.org/bots/telegram-login).

При переносе существующей базы `ADMIN_EMAIL` может выбрать прежнего администратора
для привязки к `ADMIN_TELEGRAM_ID` с сохранением ID и авторства. Задайте параметры
до его первого Telegram-входа; отдельные уже созданные аккаунты автоматически
не объединяются. Для новой пустой установки этот миграционный шаг не нужен.

После входа владельца проверьте с отдельным аккаунтом: заявка → ожидание →
одобрение → выбор «Это я» или пропуск → доступ к дереву. Для человека без Telegram
администратор может выдать одноразовую гостевую ссылку. Затем проверьте загрузку,
запись и воспроизведение с телефона, а также сохранность данных после redeploy.

## 6. Резервные копии и восстановление

Постоянный том защищает от замены контейнера, но не от потери сервера.
Скрипт приложения делает согласованную копию SQLite и связанных файлов:

```sh
node scripts/backup.mjs --data-dir /var/lib/family-space/data --out /var/lib/family-space/backups/new-copy
```

Выполните команду в терминале контейнера; для каждой копии выбирайте новое имя.
После завершения скачайте весь каталог `new-copy` **за пределы Docker-тома**.
Например, на сервере с Docker подставьте имя контейнера из Coolify:

```sh
mkdir -p ./family-memory-backups
chmod 700 ./family-memory-backups
docker cp CONTAINER_NAME:/var/lib/family-space/backups/new-copy ./family-memory-backups/new-copy
```

Перенесите копию ещё и на другой сервер или носитель с закрытым доступом.
Не ограничивайтесь копированием одного `family.sqlite` во время работы:
транзакции могут находиться в WAL, а медиа лежат отдельно.
Периодические копии можно запускать планировщиком сервера; проверяйте завершение
скрипта и наличие `manifest.json`. Настройки и ключи храните отдельно.

Для восстановления остановите приложение в Coolify и используйте Node.js 24+
со скриптами проекта либо временный контейнер того же образа, с исходной копией
и томом данных. Выполните:

```sh
node scripts/restore.mjs --from /path/to/new-copy --to /var/lib/family-space/restored --app-stopped
```

Пути должны быть доступны именно из среды, где запускается команда. `--to`
обязательно указывает на ещё не существующий каталог внутри постоянного тома;
для контейнера он должен быть доступен UID 1000. Затем задайте в Coolify
`DATA_DIR=/var/lib/family-space/restored` и запустите приложение.

Восстановление очищает сессии и незавершённые входы, отзывает старые гостевые
ссылки и не перезапускает AI-задания. Пользователям понадобится войти снова.
Проверьте дерево и воспроизведение материалов перед удалением прежнего каталога.
Подробности формата и локальные примеры — в [README.md](README.md#восстановление).
